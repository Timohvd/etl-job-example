NOG OPEN
--------

  [ ] S1 (U) HOOG  De NS-key staat in de GIT-GESCHIEDENIS (commit "etl done", via test.ipynb).
      - Er is geen remote ingesteld, dus er is niets gepusht. Je kunt de geschiedenis nog lokaal repareren.
      - Vernieuw de key in het NS-portal en trek de oude in (dat is hoe dan ook nodig: de key is ook in een
        chatgesprek getoond). Zet de nieuwe key in .env.
      - Verwijder de key uit de geschiedenis voor je ooit pusht, bijvoorbeeld met git filter-repo, of begin de
        repository opnieuw vanaf de huidige staat. Een lokale commit met de key is nog steeds een lek zodra je pusht.
      - .env bevat nog de OUDE key; vervang hem.

  [ ] S10 LAAG  SMTP zonder TLS of authenticatie. Prima voor MailHog. Voor echte mail: STARTTLS aan en
      inloggegevens via secrets.

  [ ] D11 LAAG  Volledige dagelijkse snapshots van bijna-statische data (stations). Bewust gekozen voor
      eenvoud. Bij groei: payload_hash gebruiken om alleen wijzigingen op te slaan (SCD type 2) en incrementele
      dbt-modellen.

  [ ] D18 LAAG  Airflow-metadata en data zitten in een Postgres-instance (wel in aparte databases met eigen
      rollen). Scheid ze in productie.

  [ ] Overig
      - Er is geen secrets backend; Airflow Connections + Vault/Secrets Manager is de volgende stap als er meer
        API's bijkomen.
      - De CI-workflow is nog nooit op GitHub gedraaid; pas na de eerste push zichtbaar.
      - Acties in CI zijn gepind op een tag, niet op een commit-hash (dependabot houdt ze actueel).
      - Het departures-endpoint van NS gaf 502 bij deze key (waarschijnlijk niet in het abonnement).
      - Optioneel: FastAPI + frontend op production (gebruik de rol "reader"); ML in airflow/scripts/ml/.
      - ALERT_EMAIL staat lokaal op dev@example.com (MailHog); zet een echt adres bij echte SMTP.


WAT TE DOEN BIJ HET STARTEN MET EEN LEGE DATABASE
-------------------------------------------------

  Het bootstrap-script en de migraties draaien automatisch bij "make up" op een leeg volume. De bestaande data uit
  de oude opzet is bij deze herbouw weggegooid (alleen testsnapshots; de API vult ze opnieuw).
  Een volume resetten (wist alles!):  docker compose down -v
